# 注释规范

这个项目是教材，注释的标准比一般项目高：**读代码的人应该能在不看文档的
情况下理解"这段为什么存在"**。

## 分三类写，不要混

| 类型 | 位置 | 写什么 | 例子 |
|---|---|---|---|
| 文件头 | 每个 `.h` 开头 | 所属层、职责、被谁使用、设计理由 | `connection.h` 顶部 |
| 契约 | 每个公开函数/类 | 前置条件、返回值含义、失败处理 | `handle_read()` 的注释 |
| 内部 | 关键分支旁 | **为什么**这样写，尤其是反直觉的地方 | `MSG_NOSIGNAL` 那段 |

### 硬性要求

1. **公开接口必须有契约注释**，用 `///`（Doxygen 可解析）
2. **文件头必须写"所属层"和"被谁使用"**——这是分层架构的索引
3. **解释为什么，不解释是什么**
   - ✅ `// MSG_NOSIGNAL：否则对端关闭时 SIGPIPE 会杀掉整个进程`
   - ❌ `// 调用 send 发送数据`
4. **反直觉的地方必须写**：`EPOLLOUT` 为什么要动态注册、`errno` 为什么要立刻读、
   `close` 之前为什么必须先 `epoll_ctl(DEL)`
5. **踩过的坑要留下来**：注释里出现"实测""早期版本犯过"这种话是好事

### 不写在代码里的东西

操作系统的通用知识（fd 是什么、`EAGAIN` 是什么、epoll 怎么工作）写进
`docs/basics.md`，**不要塞进源码注释**。代码注释应该服务于"读懂这个项目"，
而不是替代一本操作系统教材。
