# 1 项目地图
## 规模
- ~2000 行 C++17 · 41 个测试 · 5 层 + infra
- Windows 编辑 / WSL2 编译运行
## 一条消息的旅程
- main.cpp → ChatServer::run_once
- Server::run_once → poller_.wait
- handle_event → Connection::handle_read
- on_message → try_decode 循环取帧
- hub_.handle → vector<Outbound>
- dispatch → encode → conn.send
## 阅读顺序（自底向上）
### D0 先跑起来
- ./scripts/build.sh，再 ./build/chatroom_server
- 两个终端跑 tools/chat_cli
- 目标：亲眼看见 JOIN / MSG 的真实字节
### D1 platform（~60 行）
- unique_fd.h 30 行 = RAII 的全部意义
- sys_error.h 7 行：errno 怎么变成人能读的话
- 问题：为什么 fd 必须包一层
### D2 net（~400 行）
- 主线是 fd 的一生：accept → recv → close
- buffer → connection → server → poller → acceptor
- 关键点：EPOLLOUT 只在有积压时注册（server.cpp:63）
- 关键点：先 epoll_ctl DEL 再 close（server.cpp:73）
### D3 protocol（~190 行）
- 先读 tests/unit/test_frame_codec.cpp，再读实现
- 半包 / 粘包 / 超长 / 截断，四种边界一次看懂
### D4 chat（~250 行）
- chat_hub.cpp 是最像业务的一层
- 注意：它不认识 socket，只返回 Outbound
### D5 app（~250 行）
- chat_server.cpp = 装配 + 线程边界
- 两条铁律：连接只在 IO 线程碰；hub 单锁保护

# 2 记录系统
## 三层，别混成一层
- L1 一页纸地图：整个项目 1 页，随时改
- L2 模块卡片：每层一张，必须带文件:行号
- L3 日志：每半天 5 行，诚实写"没看懂"
## 模块卡片四栏
- 职责：一句话，不能用"处理"这种词糊过去
- 对外接口：谁调我、我调谁
- 不变量：破坏它必出 bug 的那条规则
- 未解疑问：放最上面，越靠上越该先问
## 提问三连（读任何一段代码前）
- 它解决什么问题
- 去掉它会怎样
- 我怎么用一次运行验证
## 反模式
- 抄注释当笔记（等于没写）
- 记"是什么"不记"为什么"
- 笔记里没有行号，三周后失效

# 3 思维导图
## 三种图，用途不同
- 结构图：层次与依赖，画一次，改代码时修
- 流程图：一条消息的生命周期，最常用
- 疑问图：未解决问题的树，常驻
## 节点写法
- 反例：Connection
- 正例：谁负责 close？→ server.cpp:73
- 正例：为什么 eventfd？→ adr/0003
## 原则
- 图是索引，不是正文
- 每个叶子都要能指回文件或行号
- 超过三层就该拆成两张图
